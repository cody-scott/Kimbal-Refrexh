# The dbt Semantic Layer on a star

<KimballRef chapters={[1, 2]} techniques={['Conformed Facts', 'Additive, Semi-Additive, Non-Additive Facts']}>
Kimball's goal of one consistent set of business definitions, delivered to every query tool, is what
a semantic layer automates.
</KimballRef>

A star schema already encodes much of the semantics: grain, joins, additivity. The dbt Semantic Layer
(MetricFlow) makes those semantics **machine-readable**, so BI tools, notebooks and LLM agents all ask for
`net_sales by product__category` and get the same SQL.

## The mapping

| Kimball concept | Semantic Layer concept |
|---|---|
| Fact table | Semantic model with **measures** |
| Fact grain | The semantic model's **primary entity** |
| Dimension table | Semantic model with **dimensions** and a primary entity |
| Fact FK → dimension PK | **Foreign entity** on the fact = **primary entity** on the dimension |
| Additive fact | Measure with `agg: sum` |
| Semi-additive fact | Measure with `non_additive_dimension` (e.g. take the last value over the date) |
| Non-additive ratio | **Ratio metric** (numerator / denominator from additive measures) |
| Distinct counts | Measure with `agg: count_distinct` |
| Conformed dimension | One semantic model reused by many fact semantic models |
| Role-playing date | Multiple time dimensions / entities |

## Semi-additive measures

The inventory snapshot's `quantity_on_hand` must not be summed over time. Declare it:

```yaml
semantic_models:
  - name: inventory_daily
    model: ref('fct_inventory_daily_snapshot')
    defaults: {agg_time_dimension: snapshot_date}
    entities:
      - {name: product, type: foreign, expr: product_key}
      - {name: store, type: foreign, expr: store_key}
    dimensions:
      - {name: snapshot_date, type: time, type_params: {time_granularity: day}}
    measures:
      - name: units_on_hand
        agg: sum
        expr: quantity_on_hand
        non_additive_dimension:
          name: snapshot_date
          window_choice: max    # period-end balance: last day in the period
```

Querying `units_on_hand` by month then returns the **month-end** balance, summed across products and stores.
MetricFlow enforces the semi-additive rule for every consumer.

## Querying

```bash
dbt sl query --metrics net_sales,gross_margin_pct --group-by metric_time__month,product__category
# or with MetricFlow locally:
mf query --metrics net_sales --group-by metric_time__month,store__store_region
```
