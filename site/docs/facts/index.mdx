# Module 1: Fact tables

Fact tables are where the measurements live, and where most modeling mistakes do their damage: double
counting, mixed grains and meaningless sums. This module covers what Kimball calls the *basic fact table
techniques*.

## Comparing the three fundamental types

| | Transaction | Periodic snapshot | Accumulating snapshot |
|---|---|---|---|
| Grain | One row per event | One row per entity per period | One row per process instance (pipeline) |
| Date dimensions | One (the event date) | One (the snapshot period end) | Several, one per milestone |
| Row count over time | Grows with activity | Grows predictably (entities × periods) | Grows with new instances |
| Rows updated after insert? | No (insert-only) | No (once the period closes) | **Yes**, as milestones are reached |
| Typical facts | Event amounts, quantities | Balances, levels (semi-additive), period totals | Lags, durations, milestone counts |
| dbt materialization | `incremental` (append or merge) | `incremental` by period, or `table` | `table` or `incremental` with merge |
