# Junk dimensions

<KimballRef chapters={[6]} techniques={['Junk Dimensions']}>
Order Management (Ch. 6) introduces junk dimensions for miscellaneous order flags.
</KimballRef>

Transactions come with a handful of **low-cardinality flags and codes** that don't belong to any existing
dimension: payment method, shipping method, gift flag, rush flag, order channel. Your options:

| Option | Problem |
|---|---|
| Leave them as text columns on the fact | Bloats the largest table; inconsistent values; no place for descriptions |
| One tiny dimension each | A [centipede](/facts/keys-nulls-and-hygiene#centipede-fact-tables) of foreign keys |
| Drop them | Users lose useful filters |
| **Combine them into one junk dimension** | ✓ One small key, one small table, all combinations described |

"Junk" is Kimball's tongue-in-cheek name; in practice teams call these `*_profile` or `*_indicator` dimensions.

## The lab's order profile

<DbtFile path="models/marts/orders/dim_order_profile.sql" />

The fact table looks up the combination and stores one key:

```sql
left join {{ ref('dim_order_profile') }} as op
    on  op.payment_method = o.payment_method
    and op.ship_method    = o.ship_method
    and op.is_gift        = o.is_gift
...
{{ dim_key('op.order_profile_key') }} as order_profile_key
```

## Cartesian vs observed combinations

| Build approach | When |
|---|---|
| **Cartesian product** of all allowed values (as in the lab: 3 × 3 × 2 = 18 rows) | Small value domains; every key exists before any data arrives |
| **Observed combinations** (`select distinct ... from source`) | Many flags or high-cardinality codes where the full product would be millions of rows |

With observed combinations, hash the attribute values for the key. A combination that first appears tomorrow
gets its key deterministically, and existing keys never change.

## Querying

```sql
-- Does shipping speed affect order size? And gifting?
select op.ship_speed_band, op.gift_indicator,
       count(distinct f.order_number)                         as orders,
       sum(f.net_order_amount_usd) / count(distinct f.order_number) as avg_order_value_usd
from fct_order_lines f
join dim_order_profile op on op.order_profile_key = f.order_profile_key
group by all;
```
